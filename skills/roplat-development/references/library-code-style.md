# 库代码风格：契约、算法与驱动

状态：草稿 v0（2026-11-02）。条文来自 roplat-agents 任务 `20261101-engineering-style` 的裁定（操作记录 `operations/2026/20261101-engineering-style/session-claude-win-style-01.md`，C02–C18），每条标注来源条目；强度按 D4 的三级分配，是 AI 的建议，待作者逐条定级。裁定的来龙去脉、反例与统计留在 roplat-agents，本文只写规范本身。[application-design.md](application-design.md) 第 4 节写应用代码的风格，本文写库、契约与驱动的风格，两者并列。

## 0. 适用范围、来源与强度

- **范围**（D1，C18）：自有 Rust 仓全部——roplat 与 roplat_behavior 两个工作区、drives 下的自有驱动子库、rsbullet；不含第三方 fork、vendored 代码与生成物。新代码即日适用；既有代码除 2026-11 的一次集中整改外，随触碰整改（D5）。
- **来源与优先级**（D3）：作者的六条准则加代码里已体现的 A–E 五条是第一来源；本文各条是对它们的解释；未覆盖之处以 [Rust API Guidelines](https://rust-lang.github.io/api-guidelines/) 为默认，偏离时写明例外；Clippy 的默认阈值不是来源。
- **强度**（D4）：**必须**——违反即改，评审不放行；**应当**——偏离须在代码或 PR 里写明理由；**可以**——推荐做法，不强求。
- **检查方式**：这些性质多数格式检查查不到，以评审为主；机械检查待作者解除“不配 lint”后再议（C18）。

## 1. 准则（第一来源）

作者的六条（C00 原话精简）：

1. 可复用性和合适的抽象性，过度抽象不可取。
2. API 简短、明确；过多参数是设计者的慵懒，API 须简短明确地表达其功能和目标。
3. 层次分明，不在同一个层次完成不同层次的事情。
4. 确定性优先：青睐泛型、特征等静态展开，能静态确定的东西更高效、更不易出错；但不排斥动态。
5. 对完备性的追求，与对过度防御的警惕。
6. 可读性的设计：语法与 API 贴近自然阅读顺序和逻辑。

代码里已体现、作者采纳为并列起点的五条（C02）：

- A. 不保证的也写出来。
- B. 零分配、无锁、不 spawn 是默认。
- C. 编译失败测试钉住契约。
- D. 结构归类型，参数归数据。
- E. 随机化可重现。

## 2. 抽象（准则 1）

| 强度 | 条文 | 来源 |
|---|---|---|
| 必须 | **O1 二次原则**：trait、泛型参数、关联类型、预留接口须有至少两个真实使用者；“为未来预留”不算。 | C03 |
| 必须 | **O2**：泛型参数或关联类型须换来静态检查或推导；实现者普遍忽略的参数删除。例：`MotionSpace<R>` 收为 `Space`，`ControlSpace` 去 `R`；`RelativeSpace<R>` 因 `R` 决定基座而保留。 | C03 |
| 应当 | **O3**：契约库里的生态预留写明为谁保留，且至少有一个真实使用者。 | C03、C13 |
| 必须 | **完备性高于无使用者**：O1 约束的是抽象，不是算法库的成套变体；不以“零使用”为由删除成套算法中的一个变体（六个曲线函数保留即此例）。 | C10 |
| 应当 | 同一段收束逻辑出现第二次就给它名字（节律周期的收束统一为 `execution::cycle` + `Exit::into_execution`）；一行 `node::map` 能写出的节点不进核心库。 | C03 |
| 应当 | **算法以结构体为唯一持有形态**（`new`／`plan`／`apply` 样式，如 `JointSCurve`）；需要函数形态时在调用处现场组装闭包，库不返回 `Arc<dyn Fn>`。 | C09、C11 |
| 应当 | **一个类型一个公开名**：改名后旧名不作为别名长期并存（`Latest`、`SpscQueue` 成为类型名）。 | C15 |
| 应当 | 值类型不以启发式转换吞下多种形态：`Pose` 不再从 `[f64; 7]`／`&[f64]`／`Vec<f64>` 猜测含义；一种意义一种构造。 | C09 |

## 3. API 与参数（准则 2）

| 强度 | 条文 | 来源 |
|---|---|---|
| 必须 | 参数个数在 Clippy 阈值之上的函数一律 `#[allow(clippy::too_many_arguments, reason = "…")]`，理由写进代码，不按类别豁免、不为凑阈值改签名。阈值本身、计数规则、公开／私有范围搁置待定。 | C05 |
| 应当 | **减参数的形式**：同类相邻参数成有领域名字的结构体；可选项进带 `Default` 的 `Options`；一段任务中不变的协作者进上下文对象，函数成其方法；函数的变体并为方法或选项字段。不用 builder。 | C06 |
| 应当 | 函数名表达功能与目标，不表达实现步骤；pyo3 与 libfranka 移植等“签名随对侧”的函数在 `reason` 里写明随谁。 | C05、C19 |

## 4. 层次（准则 3）

- **暂缓**：层次与归属（launch／build／CLI 是否属核心、`from_launch_params` 鸭子协议与 `MotionFile` 文件 IO 是否上移、平铺再导出）由作者同步进行的依赖关系整理裁定；核实的事实存 C07。
- 已成规范的层次事实：核心不含业务节点库（§2）；错误跨层只经正门（§5）；滤波等算法在 roplat_control，核心只留 `node::map`（C04）。

## 5. 错误（Q5）

| 强度 | 条文 | 来源 |
|---|---|---|
| 必须 | 每层定义自己的结构化错误类型；变体按调用方要区分的条件划分；字符串只出现在 `Display`。 | C08 |
| 必须 | **不再新增 `(String)` 变体**。 | C08 |
| 必须 | 跨层只经一个 `Box<dyn Error + Send + Sync>` 变体进入上层（核心为 `RoplatError::Node`），可 `downcast`；不借 `Io` 等既有变体走私。 | C08 |
| 应当 | 调用方与测试匹配变体和字段，不匹配消息文本。 | C08、C21 |
| 应当 | 一个条件一个变体也适用于控制步的退出：`ControlStep` 的 `Break` 携带 `ControlExit { Stopped, Failed(..) }`，驱动把 `Failed` 作 `Err` 返回。 | C14、C21 |
| 待定 | 契约库 `RobotException` 按条件重分变体并改名 `RobotError`，归 0.10（Q5b）。 | C08、C18 |

## 6. 静态与动态（准则 4）

| 强度 | 条文 | 来源 |
|---|---|---|
| 必须 | **`dyn` 只允许四类**：(a) 运行期才知道的选择；(b) 跨语言或 ABI 边界；(c) 异构存储；(d) 泛型参数会进入用户要写出的公共类型名，且该调用开销相对所在操作可忽略。不允许“为了少写一个泛型参数”。 | C12 |
| 必须 | 类型位置（字段、别名、公开签名）上的每个 `dyn` 带一行 `// dyn(x): …` 理由注释，x 为 a–d；局部 `&dyn` 与测试不要求。§5 的跨层正门归 (a)。 | C12 |
| 必须 | **结构归类型，参数归数据**（D）：机器人包络等编译期常量收为一个数据常量（`JOINT_LIMITS: JointLimits<N>`、`CARTESIAN_LIMITS: CartesianLimits`），不拆成一常量一字段；“未提供”写 `..JointLimits::positions(q_min, q_max)`，不用 `f64::MAX` 折算。 | C13 |
| 应当 | 包络字段名沿 roplat_msgs：`q_min`／`q_max`／`dq_max`／`ddq_max`／`dddq_max`／`tau_max`／`dtau_max`；笛卡尔六字段带 `_max` 后缀。 | C13、C17 |
| 应当 | 供调用方使用的常量（`JOINT_PACKED`）即使库内零读者也保留，文档按 O3 写明为谁。 | C13 |
| 应当 | **零分配、无锁、不 spawn 是默认**（B）：热路径上的分配、锁与任务派生须有理由，写在注释里。 | C02 |
| 必须 | **随机化可重现**（E）：带随机的算法与测试接受种子或可重现的随机源。 | C02 |

## 7. 完备性与防御（准则 5）

| 强度 | 条文 | 来源 |
|---|---|---|
| 必须 | **缺失的输入不得替换成有物理意义的数**：表达为 `Err`、`Break` 或编译错误；“保持”只能来自观测到的量。空轨迹等空输入是构造期 `Err`。 | C14 |
| 必须 | **默认实现只在对每个实现者都为真时允许存在**，否则 `Err(NotSupported)`；调用方须在编译期知道的能力拆成独立 trait（如急停）。 | C14 |
| 应当 | **不保证的也写出来**（A）：文档写明不保证什么、什么情况下返回什么，而不是默默兜底。 | C02 |
| 待定 | `Robot` 等 trait 的默认方法逐个改为 `NotSupported`、`hold_command`／`get_joint`／`get_endpoint` 改 `Option`，归 0.10（Q8c、Q8d）。 | C14、C18 |
| 不做 | panic 的接受范围与锁中毒策略，作者定为暂不处理。 | C14 |

## 8. 清理与兼容（Q9）

| 强度 | 条文 | 来源 |
|---|---|---|
| 必须 | 仓库里不留从不编译的单元；历史靠 Git，不靠保留源文件。 | C15 |
| 应当 | 再导出写明为谁而存在（`serde` 系再导出是 `#[node]` 宏生成代码所需，文档写明；纯兼容再导出删除）。 | C15、C21 |
| 待定 | 四条清理条文——不留注释掉的 `mod`、`#[deprecated]` 带版本、改名窗口一个小版本、再导出写明为谁——作者未立。 | C15、C18 |

## 9. 可读性（准则 6）

- **未立**：显式胜过简短、短名的三类许可、别名须换来静态区分，作者另定；本轮的缩写别名、`traj` 系改名与 glob 平铺均不做，事实存 C16。
- 应用层的命名规则见 [application-design.md](application-design.md) 第 4 节。

## 10. 语言（D6）

| 强度 | 条文 | 来源 |
|---|---|---|
| 必须 | 注释（`///`、`//!`、`//`）与代码内字符串（错误消息、日志、断言消息）一律英文；文档站点、记录与讨论的语言不在此条内。 | C17 |
| 可以 | 错误与日志消息以小写开头、不带句号，便于拼接。 | 本文建议 |

## 11. 测试（C）

| 强度 | 条文 | 来源 |
|---|---|---|
| 应当 | **编译失败测试钉住契约**：类型系统拒绝的写法用 `compile_fail` 文档测试或 trybuild 钉住。 | C02 |
| 应当 | 测试断言变体与字段，不断言消息文本（§5）。 | C08、C21 |
| 应当 | 不在节点或库内埋断言、计数或打印做验证；验证在调用方或测试里（与 application-design 第 4 节一致）。 | 既有 |
