# 独立使用评估任务

执行评估时，只给每个评估者提供一个下列自然任务、`skills/roplat-development` 目录、核心仓库位置，以及隔离的输出目录。不要提供 [验收规则](rubric.md)、已实现代码或前一位评估者结论。各任务只做本机有限次数 mock，不运行设备，不提交仓库。

## A：分层采样系统

请使用给定 roplat 开发技能，创建一个可运行的 Rust 小项目：一个父采样节律执行2轮，每轮进入一个校准节律执行3轮，校准的每轮再进入一个取样节律执行2轮。取样节点持有累计调用次数；整个系统连续调用两次，该状态必须保留。子节律要将本次完整执行的汇总结果返回父层，让上层汇总和单轮结果有所区别。最内层每轮还有一个临时节点，验证其创建、启用、关闭次数。请用断言验证，并展示应用的System定义；不要接入硬件。

## B：业务错误与子域恢复

请使用给定 roplat 开发技能，做一个有限的 mock 质量检查系统。第一次测试中节点输出业务Result，由一个下游节点把错误当数据处理。第二次测试显式将同样的错误作为框架失败向外传播，确认后续处理节点不执行且本层对象都按创建层关闭。第三次测试把失败放到子节律内，由父层显式处理完整执行结果并输出备用值。请实际编译运行，验证这三个情形以及对象启用/关闭次数。

## C：异步控制域旁路交换

请使用给定 roplat 开发技能，做一个无硬件的小系统：两个有限控制节律作为同一个System里的独立兄弟域运行，一个发布最新状态，另一个采样状态。用真实异步让出执行权，并在结束后确认最终状态可读；不要强制每个发布版本都被读取。同时传递一个4KiB不可变共享帧，验证旧快照在后续发布后仍有效。请说明主流图边和旁路分别承担什么，并实际运行断言。

## D：双臂取放应用

请使用给定 roplat 开发技能和 drives 仓库中的 robot_behavior，写一个无硬件的机器人应用：一台六轴机械臂依次前往上方、抓取、上方、原位四个关节目标，每段由自己的实时控制周期跟踪一条平滑参考；另一台臂在整个过程中以固定关节偏移跟随第一台。设备用实现 robot_behavior 能力 trait 的仿真臂代替。请展示 System 定义，实际运行并在调用方确认两台臂的最终位置。

## E：检测工位（同一周期内两次借出）

一台六轴臂依次访问检测位姿；每个位姿先用 robot_behavior 的 `MotionNode` 点到点到位，再借给设备节律做一段保持会话，测量节点累计周期数直到完成。全部位姿结束后把臂和每个位姿的周期数交还调用方断言。

## F：传送带跟踪（两台不同节拍的设备）

传送带是自带节拍的设备，按自己的周期推进零件并发布位置；机械臂在自己的控制会话中读取最新位置并伺服一个关节，零件离开后结束。两台设备不得锁步或用图边相连。调用方断言臂最终接近零件出口对应的目标。

## G：带守卫的控制会话与失败处理

机械臂在 System 内创建（由 System 负责连接/断开）。外层任务节律分发目标，每段控制会话含参考、伺服和步长守卫；超过步长时守卫让会话失败，不得编造零指令。在图中明确选择失败后的处理方式并说明理由，至少一个目标故意越限。调用方确认哪些目标成功、System 的结果/错误，以及失败路径上臂已断开。

E–G 的评估者可读取两个技能目录、核心 `docs/system-syntax.md` 与 robot_behavior 源码，不读取 `evaluations/`。
