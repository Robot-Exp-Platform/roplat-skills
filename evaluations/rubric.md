# 评估者之外的验收规则

本文件给审阅者，不能作为独立生成任务输入。评估需保留实际产物、编译/运行结果和必要的失败改进记录。仅解释计划、复制不执行的代码，或未经要求把应用退回手写process链都不通过。

| 通用要求 | 验收依据 |
|---|---|
| 应用使用真实 `#[roplat::system]` | 审阅调用处，核心节点连接/节律组织不是手写 process().await 链 |
| 遵守正式trait | Node::process、Lifecycle和Rhythm::drive签名正确，Rhythm所有合作式出口归还N |
| 不伪造支持能力 | 无stop_check等撤回选项，无普通if内DSL，无未知属性绕过 |
| 验证真实行为 | 编译成功并运行输出/计数/生命周期断言，失败时保留原因 |
| 作用范围正确 | 临时目录、不接设备、不改核心、不上传；没有擅自使用Python未认可节点桥接 |

## 应用写法质量

语义正确是门槛，不等于写得好。对照 `skills/roplat-development/references/application-design.md` 逐项判断，记录“满足 / 部分 / 不满足”及具体代码位置。

| 维度 | 满足的表现 |
|---|---|
| 结构表达任务 | 重复由节律产生；任务层与设备控制层分开；没有在 System 外循环调用 System 或节点 |
| 设备与节拍 | 每台设备自己的控制节律；跨设备只经旁路，没有共用节律或图边耦合两个控制域 |
| 节点粒度 | 一个节点一个职责，输入输出用领域类型；数据流在图里可见 |
| 创建位置 | 跨周期状态在外层创建，段内/周期内状态在该域头段创建；不靠手动 reset |
| 可读性 | 领域命名；头段按设备分组；System 约一屏；注释写意图而非复述语法 |
| 验证位置 | 断言在调用方或测试中；节点 `process` 内没有断言、调用轨迹或仅为测试存在的计数 |

A–C 是语义任务，允许为断言保留必要计数；D 是应用任务，写法质量的“不满足”项即视为未通过。

A：每次最内层节点应调用2×3×2=12次，重复系统后累计24；middle drive每次2，inner drive每次6；父层汇总消费child整次Output，不是最后Feed。外部节点生命周期一次，周期内临时节点每次12次启用/关闭。若自定义Input/Feed变换公式不同，按实现独立复算，不强求某个固定数值。创建层和统计方法必须清楚。

B：第一个业务Result错误不应自动使System失败；第二个应显式提升，依赖后继不得运行；第三个应使用child.outcome明确处理，不能同时混用child.output，也不能通过吞全局错误隐藏父停止。关闭逆序且没有重复启用；不把panic或丢弃Future说成正常错误归还。

C：同一个System宏包含两个独立有限Rhythm，使用Latest端点而非每次状态连一条DSL主流边；确有async Pending/yield，没有为方便使用额外OS线程。Latest允许跳版本，不能断言每读者同时同版本；在双方结束并完成最终发布后确认最终值。SharedFrame检查旧快照内容或载荷地址保持，不依赖不断覆盖的可变缓冲区借用。

D：航点序列由外层任务节律分发，每段由设备控制节律（或一层方案中的 MotionNode）执行，段内参考在任务周期头段新建；两台臂是兄弟控制域，只经 Latest 交换；使用 robot_behavior 能力 trait 而非自造设备接口。应用写法质量六项全部至少“部分”，且“结构表达任务”“设备与节拍”为“满足”。

没有实现证据不得判定成功。若任务因库能力边界无法实现，应准确指出边界；不能只因解释合理而声称行为验收通过。
